# DOCX compatibility matrix

This matrix separates repeatable OOXML structure tests from files generated by an installed office suite. Product names describe the structure being represented, not a claim that every released version has been tested.

| Profile | Evidence level | Scan | Selective removal | Non-target parts unchanged |
| --- | --- | --- | --- | --- |
| Word Transitional-style VML header | Generated OOXML fixture | Yes | Yes | Byte checked |
| Word Strict namespace with alternate prefixes | Generated OOXML fixture | Yes | Yes | Byte checked |
| WPS-style VML footer | Generated OOXML fixture | Yes | Yes | Byte checked |
| Multiple VML text shapes in one header | Generated OOXML fixture | Yes | Yes | Byte checked |
| DrawingML image anchored behind text | Generated OOXML fixture | Ambiguous candidate and safe preview | Yes, after explicit confirmation | Media and relationships byte checked |
| External DrawingML image relationship | Generated OOXML fixture | Warning; never fetched | No | Not modified |
| Unsupported embedded image format | Generated OOXML fixture | Read-only metadata, no browser preview | No | Not modified |
| LibreOffice Office Open XML export | Generated by installed LibreOffice during test | Yes | No VML candidate present | Not applicable |

The generated fixtures exercise namespace handling, header and footer parts, shape indexes when unrelated VML shapes precede a watermark, case-insensitive target matching, relationship validation, preservation of unselected shapes, DrawingML image relationships, safe image-type sniffing, and rejection of external image fetching.

## Current support boundary

The DOCX adapter supports VML text watermarks represented by `v:shape` with a `v:textpath` in numbered `word/header*.xml` or `word/footer*.xml` parts. It also reports DrawingML embedded images in those parts as ambiguous candidates. Browser previews and selective removal are limited to signature-verified PNG, JPEG, GIF and WebP bytes from internal package relationships; each image requires explicit confirmation. Removal deletes only the selected anchor or inline node, leaving shared media and relationship parts unchanged. External relationships are never fetched. The adapter does not process document backgrounds, shapes stored in the main document body, legacy `.doc` files, unsupported embedded image formats or office-suite-specific drawing objects outside this representation.

Real files saved by Microsoft Word and WPS should be added to a private local corpus before a stable release. Those files must contain only redistributable test content. Binary corpus files are intentionally not committed until their provenance and license are recorded.
